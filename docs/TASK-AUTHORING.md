# Task authoring — adding a widget or a tool

Everything this kit does on the phone is either a **widget** (a task on the home screen, installed into
`~/.shortcuts/tasks`) or a **tool** (a command in `~/.local/bin`, or a maintainer script that stays in the repo). Both are
plain scripts with a header, and both have gates around them that fail until the surrounding pieces agree.

This page is the shortest path from "I want it to do X" to "it is in the repo, installed, translated and green".
Read `CONTRIBUTING.md` §十一 first — the gates already exist, do not invent new ones.

## 0. Which one are you adding?

| you want | add a | closest existing example |
|---|---|---|
| one tap on the home screen that does a job (start, stop, back up, recover) | widget | `widgets/11_update-apps.sh` |
| a command the Console app or the page panel can trigger, or that you run from a shell | runtime tool | `tools/dsh-kit-update` (bash), `tools/dsh-status-pub` (python) |
| a button / switch / lamp / read-only row in Console + Bridge + page panel | a control in `ui/controls.json` (plus, usually, a widget behind it) | `ui/controls.json` |
| something only you run while developing | a script in `tools/` **without** the `# install: runtime` marker | `tools/i18n-audit` |

## 1. Add a widget (the 13th)

### 1.1 The file

    widgets/NN_slug.sh

* `NN` — the next number, zero-padded like the existing ones (`0_` … `11_`, so `12_`). It is the **order in the
  Termux:Widget list**; `0_emergency-stop` is 0 on purpose (it is the one you reach for in a panic).
* `slug` — lowercase, hyphens, English (`12_rotate-logs.sh`). The repository's face is English; the Chinese name is a
  forwarder alias, not the file name.

Header, copied from a live widget (`widgets/11_update-apps.sh:1-22`):

```bash
#!/data/data/com.termux/files/usr/bin/bash
# 12_rotate-logs — one line saying what it does
#
# 为什么要有它：<why this exists — the failure it prevents, and when it was hit>
#
# Usage: 12_rotate-logs.sh [--dry-run]
HOME_DIR="${DSH_HOME_DIR:-/data/data/com.termux/files/home}"
. "$HOME_DIR/.local/share/dsh-widgets/common.sh"
```

`widgets/common.sh:2` states the house rules — **one line per step + ✔/✘; verify whatever can be verified; always poll
instead of sleeping blindly; idempotent; supports `--dry-run`.**

* Every user-visible line goes through the helpers (`step`, `ok`, `warn`, `bad`, `die`, `say`, `log`). They route text
  through `dsh_msg`, which is what makes the language switch reach your new widget **with no call-site changes**.
* `--dry-run` must print and do nothing — both READMEs promise this for every widget (`README.md:117`).
* The script sources the **installed** library copy, so either run it after `tools/install-widgets`, or point
  `DSH_HOME_DIR` at a throw-away home that has `~/.local/share/dsh-widgets/` populated — that is what
  `tests/ci-selftest.sh` does.

### 1.2 Give it a Chinese name (a gate, not a nicety)

Add one line to the `MAP` in `tools/install-widgets:25-29`:

    [12_轮转日志]=12_rotate-logs

`install-widgets` walks `widgets/[0-9]*.sh` and prints
`⚠ repo task … has no Chinese name (add one to MAP)` for anything missing. Why it matters: Termux:Widget lists every
file in `~/.shortcuts/tasks`, so an unnamed task shows up as a **single English row** among Chinese ones — that is how
`10_net-fix` was noticed. Then:

```bash
bash tools/install-widgets --dry-run    # prints every install it would do, writes nothing
bash tools/install-widgets              # ~/.shortcuts/tasks/<en>.sh + a <zh>.sh forwarder + the shared libraries
```

Installed: `~/.shortcuts/tasks/<english>.sh`, a Chinese forwarder that `exec`s it (so shortcuts already on the home
screen survive a rename), and `common.sh` / `i18n.sh` into `~/.local/share/dsh-widgets/`. Editor leftovers
(`*.bak-*`, `*.orig`, `*~`) are moved to `~/.shortcuts/.stale` — a dead entry on the home screen is a bug.

### 1.3 Its text, so it can be translated

User-visible strings go into **`i18n/zh.json`** — the only translation file a human edits. Then:

```bash
tools/i18n-table add patch.json   # merge {"English source": "中文"} pairs and regenerate
tools/i18n-table gen              # rewrite the generated blocks from i18n/zh.json
tools/i18n-table check            # fail if a generated block drifted (a CI gate)
```

`gen` writes three blocks: `widgets/i18n.sh` (bash `declare -A DSH_ZH`), `apps/bridge/…/Lang.java` and
`apps/console/…/Lang.java`. They sit between `>>> generated by tools/i18n-table` and `<<<` markers and **must not be
hand-edited** — the next `gen` overwrites them. A missing key degrades to English on purpose (never an empty string,
never a key name, never an error). Details: `docs/i18n.md`.

### 1.4 If the panel or the Console should trigger it

1. Add a control to `ui/controls.json` (`"task": true` for a widget-backed button; `kind` is
   `button` / `switch` / `lamp` / `text`).
2. `tools/ui-controls gen` — regenerates the panel's `client.js` block, both `UiControls.java`, both `Palette.java`
   (from `ui/theme.json`), both `res/values/dsh_theme.xml`, and merges new strings into `i18n/zh.json` (then run
   `i18n-table gen`). `tools/ui-controls check` compares only and exits 1 on drift.
3. Whitelist the task name in `tools/dsh-tasksd` (`ALLOWED`, `:63-65`) — only whitelisted names can be run from the
   panel; anything else returns `not in the whitelist`.
4. If it is destructive, add it to `DANGEROUS` in **both** `tools/dsh-tasksd:98` and `tools/dsh-status-pub:34`
   (two copies, both live).
5. `tools/check-task-ids` proves the id agrees in all four places: the tasksd whitelist, the Console, the panel and the
   widget script. Run it — it exists because those four once disagreed.

### 1.5 The counts and lists that say "12"

A stale count is invisible in review — and a hand-written list of "where the number lives" goes stale the same way
(this section used to carry one). Two things instead:

```bash
python3 tools/check-counts        # 字面量与 widgets/ 实际不符就报错（--strict 是目标形态）
grep -rn "[0-9]* widgets\|[0-9]* 个小组件\|Twelve" README.md README.zh-CN.md tools/ widgets/ tests/ docs/
```

`tools/check-counts` is the (h) gate: it counts `widgets/[0-9]*.sh`, compares every `N widgets` / `N 个小组件`
literal it finds, and fails on a mismatch (it also lists the literals that still agree, so the list of places to
"reference the source instead" stays visible). CHANGELOG entries and `docs/DSH运维笔记.md` are excluded on purpose —
the repository freezes published history (`CHANGELOG.md:4`). New widgets should keep the number out of comments and
docstrings at all; the durable places (README lists, the `### N widgets` heading) are still literals and are the
next thing to make reference the source.

If you add a document under `docs/`, also add it to the `docs/` row of `## Repository layout` in both READMEs.

### 1.6 Test it

`bash tests/selftest.sh` walks every widget; the destructive ones only rehearse by default. It is heavy on the phone —
`CONTRIBUTING.md` §十一 says which jobs do not run in CI. `tests/lib-tests.sh` covers `widgets/common.sh` itself.

## 2. Add a tool

* Name it `tools/<name>` — no extension for bash, `.py` for python. User-facing runtime tools take the `dsh-` prefix;
  maintainer-only scripts do not.
* Header, from `tools/dsh-kit-update:1-16`: shebang, optional `# install: runtime` marker, `# <name> —— <purpose>`,
  the why-block, `# Usage:`.
* **`# install: runtime`** is what puts it in `~/.local/bin`: `tools/install-tools` copies the files that carry the
  marker and leaves the rest in the repo (7 tools carry it today). Without the marker a new tool silently stays in the
  repo and every call from the phone misses it. `tools/install-tools --check` is the gate; `droid` is skipped on purpose
  (see `SKIP`).
* Replace atomically: `tools/install-tools` installs to `$DST/.$b.new` and then `mv -f`. A running script truncated in
  place is read broken.
* Read shared facts instead of guessing them — the DSH port comes from `tools/dsh_common.py` (`~/.dsh-url`), because two
  tools hard-coding 8080 once disagreed with each other.
* `--check` should report only and exit non-zero on drift; `--dry-run` prints and writes nothing.
* Static gates: `tools/ci-shellcheck.sh` (`bash -n` + shellcheck over every script), `mypy.ini`, `ruff.toml`. Python
  unit tests live in `tests/unit/` (pytest); shell assertions about the shared libraries live in `tests/lib-tests.sh`.

## 3. Before you push

`CONTRIBUTING.md` §三 (checklist) and §十一 (the gate table) — run the ones that apply, then:

* a CHANGELOG entry under `## [Unreleased]` (§六; a pure documentation commit does not need a version bump),
* `tools/pre-push-check` (the scripted version of §三) and `tools/check-no-secrets.sh`,
* publish: `publish.ps1 -DryRun` then `publish.ps1` — it **refuses to push when files changed but `CHANGELOG.md` did
  not**.

## 4. When a gate fails

| gate | what it is telling you |
|---|---|
| `tools/install-widgets` ⚠ no Chinese name | add the `MAP` line |
| `tools/check-task-ids` | the same id differs across the whitelist / Console / panel / script |
| `tools/ui-controls check` | a UI string or colour was edited by hand instead of in `ui/controls.json` / `ui/theme.json` |
| `tools/i18n-table check` | a generated translation block drifted from `i18n/zh.json` |
| `tools/i18n-audit` | a `Lang.t()` argument is not a literal, a control has no Chinese, two themes differ, … |
| `tools/install-tools --check` | the repo tool and the installed copy differ — you are reasoning about code you are not running |
| `publish.ps1` "files changed but CHANGELOG.md did not" | exactly that; see §六 |
