DSH 控制台 v0.5.1（包名 io.dsh.console，versionCode 6）
=====================================
它是什么
  这套 Termux 环境的"遥控器"：把 9 个桌面组件做成一个正经 App + 一个桌面小部件。
  它自己不做任何计算，只是请 Termux 帮忙跑命令（走官方通道 com.termux.RUN_COMMAND）。

权限（只有 1 个，可在系统设置里核对）
  · com.termux.permission.RUN_COMMAND —— 由 Termux 定义的权限，用来让别的 App 请它执行命令
  没有：存储访问 / 网络 / 无障碍 / 悬浮窗 / 读应用列表 / 开机自启

前提
  · Termux 已装，且 ~/.termux/termux.properties 里 allow-external-apps = true（本机已开）
  · 若 App 内提示缺权限：设置 → 应用 → DSH 控制台 → 权限 → 允许 RUN_COMMAND

怎么用
  1) 打开「DSH 控制台」→ 点「刷新状态」→ 顶部三个灯变色（绿=在跑 黄=半死 红=没有）
  2) 按分类找按钮：启动/停止 · 通道 · 维护 · 紧急
  3) 「日志」按钮单独一屏：所有发送、回传、退出码、原始输出都在里面（可复制、可清空）
  4) 长按桌面空白 → 小部件 → 拖出「DSH 控制台」→ 桌面直接有：三灯 + 启动/连adb/唤醒桥/刷新

安全与撤销
  · 卸载 App 即可，不影响 Termux 与 DSH 本身
  · 它不持有任何长期通道：每次执行都是一条一次性命令，Termux 侧随时可以关掉 allow-external-apps 让它失效

v0.3 修的问题（你截图里看出来的）
  · 灯的颜色：v0.2 把颜色涂到了字母/汉字上（索引写死 0/4/8），
    所以「文字写着 桥 v1.8、灯却是灰的」。现在按圆点实际位置动态上色，灯后面的名字也跟着变色。
  · 输出区重复三遍「已发送：刷新状态」：进前台时 onCreate 与 onResume 各发一次。
    现在有在飞的不发、缓存新鲜不发、15 秒内不重复发。
  · 忙碌时其他按钮看不出变灰：文字改按「启用/禁用」两态给色，禁用色明显更暗。

v0.4：把「桥」和「adb」彻底拆开（它们本来就是两条独立的通道）
  · 桥 = 无障碍 App + 127.0.0.1:8788 + token，走回环，**不需要网络**
  · adb = 无线调试 + wlan 接口，**必须有可用 Wi-Fi 网络**
  界面上的对应改动：
    「连 adb」  → 只做无线调试那条（组件 8）
    「唤醒桥」  → 只做无障碍那条（dsh-bridge wake，带 token 的广播，必要时自动重新授权）
    「看桥状态」→ 只查桥：端口 / 是否真应答 / 版本 / paused
    「全部恢复（adb + 桥）」→ 两条都要时才用（组件 7，失败也会各自说明是谁的问题）
  桌面小部件的四个按钮同样拆开：启动 / 连 adb / 唤醒桥 / 刷新。

  附带修掉一个隐患：小部件里「连 adb」按钮和 adb 指示灯的 id 撞了（都叫 w_adb），
  RemoteViews 会把点击挂到灯上 → 现在灯用 w_lamp_*、按钮用 w_btn_*，各不相干。

v0.5：底下的输出框改成「日志」按钮 + 按钮按功能分类
  ① 输出框不再常驻在页面底部
     · 之前那块框没内容时就是一片空白，看着像坏了；现在改成右上角的「日志」按钮
     · 点开是独立一屏：发送记录 / 回传 / 退出码 / 耗时 / 原始输出，可滚动、可长按选中
     · 三个按钮：复制全部、清空、关闭（清空只清显示，不动 Termux 侧任何东西）
     · 有未看过的记录时按钮上带角标：「日志 (2)」，点开即清零
     · 等结果的时候日志按钮**不会**变灰 —— 可以边等边翻记录
  ② 底部只留一行「最近一次结果」摘要：✅ 绿 / ⚠ 红 + exit 码 + 耗时 + 时间，点它也能开日志。
     一条记录都没有时这一行不显示（不再留空白框）
  ③ 按钮按功能分成四段，每段一个蓝色小标题：
     · 启动 / 停止：启动 DSH · 打开 Web UI · 软重启 · 硬重启 · 关闭 DSH
     · 通道（adb 与桥分开）：连 adb · 唤醒桥 · 看桥状态 · 全部恢复（adb + 桥）
     · 维护：备份 · 清理
     · 紧急：紧急停止（红色按钮，二次确认）
  ④ 对话框改成深色主题（之前系统默认亮色，在深色页面上白一块）

v0.5.1：实机装上 v0.5 后自检，当场抓到两个问题（都是"看着像坏了/看着像没出错"的那种）
  ① 日志里冒出 `[errmsg] -1`
     原因：Termux 结果 bundle 里的 `err` 是**整数错误码**，只有 `errmsg` 才是字符串消息；
     我把 `err` 当消息打了出来 → 现在只有真有文字的 errmsg 才追加，纯数字一律不显示。
  ② 任务失败后，"最近一次结果"会被覆盖成 `✅ 刷新状态`
     原因：任何任务跑完，Termux 侧都会自动补一次状态刷新；那次回传把刚失败的
     `⚠ 连 adb exit=3` 刷成了 `✅ 刷新状态 exit=0` —— 看起来像刚才根本没失败。
     现在只有**用户点的那一次**才会更新那一行摘要。
  这两条都是"跑起来才发现"的：单看代码不容易觉得有问题，装上去点两次就露出来了。

装 APK 在这台机器上的真实流程（实测，别再踩）：
  1) 版本号不变 → 安装器只说「已安装相同版本（x.y）」；**版本号变了**才会走「超级守护」页；
  2) 「超级守护」页底部那个大按钮是 **「取消安装」** —— 点它就等于取消；
  3) 唯一的入口是那行小字「…若信任该应用，您可授权本次安装」的**蓝色后半段**
     （实测只有 "安装" 两字附近响应，点在 "授权" 上没反应）；
  4) 之后系统弹「安全验证」：指纹 or 「锁屏密码验证」，**约 50 秒不操作会自己超时，安装不会发生**；
  5) 想确认到底装上没有：**再打开一次同一个 APK** —— 显示「已安装相同版本（x.y）」才是真装上了。
     （App 里显示的版本号不可靠：更新后旧进程还活着，看到的还是旧版本）
  6) 想彻底免掉这一套：把「无线调试」打开一次，用 adb 的 `pm install` 静默安装，不需要任何验证。

v0.6.1（versionCode 8）：**当前版本，已装并逐项验证**。修两个"点出来才发现"的 bug：
  ① **「唤醒桥」「看桥状态」两条一直是坏的**：它们执行的命令写的是裸名字 `dsh-bridge wake`，
     而 RUN_COMMAND 走的是 `bash -lc`，实测它的 PATH 只有 `/data/data/com.termux/files/usr/bin:.`
     ——**没有 `~/.local/bin`** → 两条命令全是 `exit=127`（command not found）。
     实测复现：`env -i bash -lc 'command -v dsh-bridge'` → NOT FOUND。
     **改**：改写成绝对路径 `$HOME/.local/bin/dsh-bridge ...`；修完实机实测：看桥状态 exit=0
     并回传「桥：在监听且应答　版本 v1.8　paused=false」，唤醒桥 exit=0（0.118s）。
  ② **状态刷新的"最近一次结果"从来没出现过**：v0.6 里我在 isStatus 分支里把 `pending` 先清了、
     再读 `wasPending` → 永远是 false → 摘要行不显示（实机点两次才发现摘要区空着）。
     **改**：先取 `wasPending` 再清；实机验证：点「刷新状态」→ 摘要行显示 `✅ 刷新状态 exit=0 0.171s`。

怎么撤销你的密码授权（三个入口，任选其一，都不需要看屏幕/点按钮以外的依赖）：
  1) 控制台 App →「紧急」→『撤销安装密码授权』（红色按钮，二次确认）
  2) Termux 桌面小组件 → `9_撤销安装密码授权`
  3) 终端里直接 `rm ~/.dsh-install-pass`（或 `dsh-install-pass revoke`）
  撤销后想恢复：把 6 位密码再给我一次（`printf 密码 | dsh-install-pass set`），或者你自己按指纹。

v0.8（versionCode 11）：**授权改成开关**（你说"应该做一个开关，而不是一个按钮"）
  · 位置：控制台「维护」类下面 ——「安装密码授权」+ 一个 Material 开关，下面一行写当前状态：
      开：当前：已授权（AI 可以装包）　（绿色）
      关：当前：未授权（装包要你按指纹或重新授权）（灰色）
  · **拨到关**：弹出确认「等于撤销：删掉 ~/.dsh-install-pass」→ 点「撤销」→ 文件立刻删掉，
    状态行变未授权（实测 0.115s，撤销后 `dsh-install-apk` 会以退出码 3 拒绝装包）。
  · **拨到开**（在未授权时）：弹出输入框要那 6 位数字 → 点「授权」→ 写回 600 文件、状态行变已授权。

  · 开关不是本地记的：每次进前台/回前台都会静默问一次 helper（`dsh-install-pass status`），
    所以你在别处（小组件 9 / 终端 rm）撤销过，这里也会如实显示未授权。
  · 顺带修：App 侧回传区分「状态整包」与「任务输出尾部」两种截断规则（见 v0.7.1），

v0.9（versionCode 12）：**语义纠正** —— 这个开关管的是「AI 能不能动用你的密码」，不是「能不能装包」
  你那句话点醒了我：那 6 位是**系统身份验证的通用凭据** —— 装 APK 要过「安全验证」，
  解除应用的"设置限制"、开发者选项里的敏感确认……弹的都是它。所以：
  · 开关改名：~~安装密码授权~~ → **密码使用权**
  · 说明改成：「打开＝AI 可用你那 6 位锁屏密码替你过身份验证（装包、解除设置限制等）；关掉＝立刻收回」
  · 状态行：已授权（AI 可代你过身份验证）／未授权（任何需要密码的验证都得你本人来）
  · 收回确认框里列清楚会产生什么后果：装包的「安全验证」、解除设置限制、开发者选项的敏感确认
    都会停在你这儿；恢复时明确写"用途仅限：替你过系统身份验证"。
  · 文件与工具同步改名（旧的自动迁移）：
      ~/.dsh-install-pass → **~/.dsh-auth-pass**（600）
      dsh-install-pass    → **dsh-auth-pass**（status/set/revoke/digits/path）
      小组件 9_撤销安装密码授权 →**9_撤销密码授权**
  · **我给自己的规矩（也写在这儿让你能查）**：这个密码只在"替你过系统身份验证"时读
    （装包、解除设置限制这类你让我做的事）；**绝不**用于解锁手机翻内容、支付/免密、
    或任何与当次任务无关的场景。撤销入口三个：这个开关 / 小组件 9 / `rm ~/.dsh-auth-pass`。

v1.0（versionCode 13）：**超时改成按任务算 + 文案说实话**（起因：00:10 那条假警报）
  你贴的日志里有一行：`00:10:34 已发送：自动刷新状态` → `00:11:19 ⚠ 超过 45 秒没有收到 Termux 回传`，
  后面列的原因（未授权 / allow-external-apps / 后台启动被拦）**全是错的方向**。实测真相：
  · 那个时刻我在跑 58 项自检（含 1GB 备份 + 沙箱 DSH 启动），**手机 load 冲到 7.11**；
  · 状态文件停在 16:10:07，之后**没有新写入** → 那两次请求**根本没执行**（不是权限问题）；
  · 现在同一条命令的正常耗时是 **0.13 秒**。
  改动：
  ① **按任务给等待窗口**（以前所有任务共用 45 秒 → 备份/清理/重启这类本来就要 1~5 分钟的任务
     每次都假报警）：启动 240s、软/硬重启 300s、关闭 200s、连 adb 220s、全部恢复 280s、
     备份/清理 420s、紧急停止 180s、看桥状态 40s、查询类 25s。
     忙碌行也写清楚：「正在执行：X　已等待 Ns（这条通常 ≤Ns）」。
  ② **查询类超时会自动补发一次**（手机上"忙一下"很常见，重发基本就好），
     只有连着两次都没回音才报错，文案第一条就是"手机当时很忙（后台在跑备份/自检之类）"。
  ③ **自动刷新不再写日志**（以前每进一次前台就多一条"已发送：自动刷新状态"，把真结果淹了）；
     手动点「刷新状态」仍然记录，摘要行照常显示 ✅/⚠。
